### 1. キャリブレーション研究 — LLMの信頼度と実際の精度の比較

**目標:** LLMが出力する信頼度スコアが、実際の予測精度と相関しているかどうかを検証する。

**重要性:** DSTの割引ステップでは、各証拠ソースの質量に信頼度スコアを掛けます。LLMの信頼度スコアが適切にキャリブレーションされていない場合（例：実際の信頼性に関係なく常に0.7を出力する場合）、割引ステップが無効になります。

**実装方法:**

1. **予測を収集**: 正解ラベル付きの大規模データセット（100人以上のユーザー）でパイプラインを実行する。
2. **生の信頼度値を記録**: 各ユーザーおよび各証拠ソース（A/B/C/D）について、LLMの `conf_X` 値と、そのソースの個別予測および最終予測を記録する。
3. **信頼度でビニング**: 予測を信頼度区間（例：0.0-0.2, 0.2-0.4, ..., 0.8-1.0）でグループ化する。
4. **ビンごとの実際の精度を計算**: 各信頼度ビン内で、実際に正しかった予測の割合を計算する。
5. **信頼性図をプロット**: 理想的なキャリブレーション曲線は対角線（信頼度＝精度）になる。偏差は過信または過小評価を示す。
6. **補正を適用**: LLMが体系的に過信している場合、キャリブレーション関数（Plattスケーリングやアイソトニック回帰など）を適用して、生の信頼度をキャリブレーション済み信頼度に変換してから割引する。

```python
# 分析の擬似コード例
for bin in confidence_bins:
    users_in_bin = [u for u in results if bin.lo <= u.conf < bin.hi]
    actual_accuracy = sum(u.correct for u in users_in_bin) / len(users_in_bin)
    print(f"信頼度 {bin}: 予測 ~{bin.mid}, 実際 {actual_accuracy}")
```

### 2. 識別枠の拡張 — 複合仮説

**目標:** 二値の地域分類（関東 vs 非関東）を超えて、より豊かな地域推定を実現する。

**重要性:** 現在の二値枠では情報が失われます。ユーザーが東京、大阪、名古屋のいずれかに居住している場合、それぞれ異なる証拠パターンを持ちますが、「関東／非関東」に集約されてしまいます。

**実装方法:**

1. **より豊かな枠を定義**: `Θ = {東京, 神奈川, 埼玉, 千葉, 大阪, 名古屋, 福岡, ...}`
2. **複合仮説をサポート**: DSTは `{東京, 神奈川}` のような部分集合（＝「南関東」）を自然に扱えます。`dst_engine.py` を修正して、シングルトン以外の焦点要素を処理できるようにします。
3. **LLMプロンプトを更新**: モデルに個別の都道府県や地域グループに質量を割り当てるよう指示します。
4. **べき集合の処理**: N個の仮説に対して、完全なべき集合は2^N個の要素を持ちます。実用上は、事前定義された「意味のある」部分集合（例：地方区分）に制限します。

```python
# 拡張された質量関数の例
mass = {
    frozenset({"Tokyo"}): 0.3,
    frozenset({"Tokyo", "Kanagawa", "Saitama", "Chiba"}): 0.2,  # 関東地方
    frozenset({"Osaka"}): 0.1,
    "Omega": 0.4,  # 完全枠
}
```

**数学的な変更点**: Dempsterの結合ルールはすでにこれをサポートしています — 2つの部分集合 A ∩ B の交差は集合論的に計算されます。現在の実装は、辞書キーのマッチングから適切な集合交差に拡張する必要があります。

### 3. コンフリクト対応の判定ロジック

**目標:** 高コンフリクトのユーザーを、不正確な予測をする代わりに手動レビュー用にフラグ付けする。

**重要性:** 証拠ソース間のコンフリクトが高い場合、通常 (a) 人間の判断が必要な矛盾する証拠、または (b) 意図的に身元を隠蔽しているユーザーのいずれかを示します。これらのケースで予測を行うと、システムへの信頼が低下します。

**実装方法:**

1. **コンフリクト閾値を定義**: 経験的分析に基づいて、ペアワイズコンフリクトのどのレベル（例：K > 0.3）が信頼性の低い融合を示すかを決定します。
2. **レビューフラグを追加**: 結果に、高コンフリクトケースの `"needs_review": True` フィールドを追加します。
3. **コンフリクトソースを分類**: どの証拠ソースのペアが最もコンフリクトが高いか、またその理由を報告します。
4. **代替結合ルールの実装**: 高コンフリクトのシナリオでは、YagerのRule（コンフリクト質量を正規化ではなくOmegaに割り当てる）やMurphyの平均ルール（結合前に質量関数を平均化する）の使用を検討します。

```python
# コンフリクト対応判定の例
def decide_with_review(mass, conflict_metrics, conflict_threshold=0.3):
    if conflict_metrics.max_pairwise_conflict > conflict_threshold:
        return {
            "prediction": "REVIEW",
            "reason": f"高コンフリクト ({conflict_metrics.max_pairwise_conflict:.2f}) "
                      f"ソース間: {conflict_metrics.most_conflicting_pair}",
            "needs_review": True,
        }
    return decide(mass)
```

### 4. 構造化ログ

**目標:** print文をPythonの `logging` モジュールに置き換え、本番環境レベルの可観測性を実現する。

**実装方法:**

1. **ログレベルの設定**: DST数学の詳細には `DEBUG`、進捗には `INFO`、API問題には `WARNING`、障害には `ERROR` を使用します。
2. **ファイルハンドラの追加**: コンソールに加えて `pipeline.log` にもログを出力します。
3. **構造化フォーマット**: タイムスタンプ、ユーザーID、バッチ番号を含めます。

### 5. マルチソース属性DST

**目標:** 年齢と性別の推定にも、地域推定と同じDSTマルチソース融合アプローチを適用する。

**実装方法:** 属性推定のLLM呼び出しを3つの独立した証拠ソース（テキストベース、画像ベース、Bio/ハンドルベース）に分割し、それぞれから独立に質量関数を抽出して、DempsterのRuleで融合します。これは地域推定パイプラインと全く同じ構造になります。

### 6. アンサンブルLLM融合

**目標:** 複数のLLM呼び出し（または異なるモデル）を独立した証拠ソースとして使用し、DSTで融合する。

**実装方法:** 同じプロンプトを2〜3の異なるモデル（例：Gemini Flash、Gemini Pro、GPT-4o）で実行し、各モデルの出力を独立した証拠ソースとして扱い、DempsterのRuleで結合します。これにより、個別のモデルのバイアスに対する自然な頑健性が得られます。
